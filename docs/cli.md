# Справочник CLI

Все команды запускаются через `uv run muscriptor <команда>` из корня
репозитория (или через установленный бинарник `muscriptor`, если пакет
установлен). Полный список — `uv run muscriptor --help`; справка по
конкретной команде — `uv run muscriptor <команда> --help`.

Содержание:

- [transcribe](#transcribe) — аудио → MIDI/события/ноты
- [serve](#serve) — HTTP-сервер и веб-интерфейс
- [list-instruments](#list-instruments) — список названий инструментов
- [arrange-guitar](#arrange-guitar) — MIDI → аппликатура (JSON)
- [guitar-tab](#guitar-tab) — arrangement.json → ASCII-таб (и MIDI)
- [guitar-musicxml](#guitar-musicxml) — arrangement.json → MusicXML
- [Список инструментов](#список-инструментов)

## transcribe

```
uv run muscriptor transcribe АУДИО [опции]
```

Транскрибирует аудиофайл. Читаются WAV, MP3, FLAC, OGG, M4A, AIFF, Opus и
всё, что умеет libsndfile; формат определяется по содержимому, а не по
расширению. Результат по умолчанию — MIDI рядом с входным файлом.

### Опции

| Опция | По умолчанию | Описание |
|---|---|---|
| `--output`, `-o` | `<аудио>.<ext>` | Путь результата. `-` — писать в stdout (весь прогресс уходит в stderr). Для `--format sheets` это **каталог**: он должен не существовать или быть пустым. |
| `--format`, `-f` | `midi` | `midi` \| `json` \| `jsonl` \| `sheets` (см. ниже). |
| `--notes` | выкл. | Печатать декодированные события в stderr. |
| `--sampling` | выкл. | Сэмплирование вместо жадного декодирования. |
| `--temperature`, `-t` | `1.0` | Температура сэмплирования (только с `--sampling`). |
| `--cfg-coef` | `1.0` | Коэффициент classifier-free guidance. |
| `--model`, `-m` | `medium` | `small`/`medium`/`large`, путь к `.safetensors`, `hf://…` или `http(s)://…`. |
| `--device`, `-d` | `auto` | `auto`, `cpu`, `cuda`, `cuda:0`, `mps`, … |
| `--dtype` | по устройству | `float32` \| `float16` \| `bfloat16`. По умолчанию `float16` на MPS, `float32` на остальных. |
| `--batch-size`, `-b` | `1` | Чанков за один проход. Значения > 1 снижают качество на границах чанков и требуют `--no-prelude-forcing`. Без форсинга: 4 на GPU, 1 на CPU. |
| `--strict-eos` | выкл. | Падать с ошибкой, если чанк не выдал EOS за бюджет генерации (по умолчанию — предупреждение). |
| `--beam-size` | `1` | Ширина beam search (1 — жадное декодирование/сэмплирование, ≥ 2 — beam search). |
| `--prelude-forcing` / `--no-prelude-forcing` | вкл. | Учительски форсировать tie-пролог каждого чанка по незакрытым нотам предыдущего — чанк не может «перезапуститься» с неправильными инструментами. Требует `--batch-size 1`. |
| `--auralize` | — | Записать стерео-смесь: L = оригинал, R = синтез MIDI. Формат по расширению (`.wav` по умолчанию или `.mp3`). Требует FluidSynth; только с `--format midi` и не при `-o -`. |
| `--soundfont` | — | Путь к `.sf2` для `--auralize`. По умолчанию `MuseScore_General.sf2`, скачивается один раз и кэшируется. |
| `--instruments` | — | Список ожидаемых групп инструментов через запятую. Жёсткое ограничение: всё остальное не будет декодировано. Регистр не важен, однозначные сокращения допустимы (`timp,cello,dist`). |
| `--remove-vocals` | выкл. | Отделить ведущий вокал (audio-separator, Mel-Band-RoFormer) и расшифровать инструментал. Оба стема сохраняются в `<аудио>_stems/`. Нужен ffmpeg. |
| `--detect-tempo` | `best-effort` | `true` — падать, если устойчивый темп не найден; `best-effort` — предупредить и использовать заглушку 120 BPM без размера; `false` — не определять темп вообще. |

### Форматы вывода

- **`midi`** — `.mid`-файл с темпом/размером (если темп определён). Ноты
  сдвигаются на измеренную задержку онсетов, тактовая черта ставится по
  первому сильному бейту, короткие ноты валидируются, перекрытия обрезаются —
  ровно те же байты, что отдаёт сервер.
- **`json`** — один JSON-массив событий:

  ```json
  [
    {"type": "start", "pitch": 64, "start_time": 1.23, "index": 0, "instrument": "electric_bass"},
    {"type": "end",   "end_time": 2.10, "start_event_index": 0}
  ]
  ```

- **`jsonl`** — то же, но по одному событию в строке, с `flush` после каждой
  строки: файл (или `-o -` pipe) можно читать в реальном времени. События
  прогресса в файл не пишутся.
- **`sheets`** — каталог нот, гравируемый MuseScore 4+ (см. ниже).

### Нотный лист (`--format sheets`)

```bash
uv run muscriptor transcribe song.mp3 --format sheets --output score/
```

Требования: **MuseScore 4+** в системе (см.
[installation.md](installation.md#musescore-4--ноты-в-pdfmusicxml); путь можно
задать через `MUSCRIPTOR_MUSESCORE`). Каталог вывода должен быть пустым или
отсутствовать — проверка выполняется до загрузки модели. Ноты гравируются по
квантованным нотам (сетка определяется по темпу), поэтому лучше всего
работает музыка с устойчивым ритмом; рубато-записи читаются хуже.

В каталоге появляются:

```
score/
├── score.mid                       квантованная транскрипция
├── score.musicxml                  партитура MusicXML
├── full_score.pdf                  все инструменты на одной системе
├── 01_electric_guitar.pdf          PDF по инструменту…
├── 01_electric_guitar_tab.pdf      …и табулатура для ладовых инструментов
├── 02_electric_bass.pdf
├── 02_electric_bass_tab.pdf
└── 03_drum_kit.pdf
```

Нумерация — позиция партии в партитуре; табулатура создаётся для всех партий,
у которых инструмент MuseScore имеет подходящее число струн (4–9).

### Примеры

```bash
uv run muscriptor transcribe song.mp3                      # song.mid
uv run muscriptor transcribe song.mp3 -f jsonl -o - | jq . # поток событий
uv run muscriptor transcribe song.mp3 -f sheets -o score/  # PDF + MusicXML
uv run muscriptor transcribe song.mp3 --remove-vocals      # без ведущего вокала
uv run muscriptor transcribe song.mp3 --instruments bass,drums --sampling -t 0.9
uv run muscriptor transcribe song.mp3 --auralize mix.wav   # L=оригинал, R=MIDI
uv run muscriptor transcribe song.mp3 --detect-tempo false # без метронома
```

### Полезно знать

- Прогресс, тайминги и предупреждения всегда пишутся в **stderr**; stdout
  зарезервирован под результат при `-o -`.
- При `--format midi --notes` вместо событий выводится подсказка
  использовать `--format json` — из MIDI события уже не восстановить.
- Если модель не успевает закрыть ноту (чанк закончился, а EOS не пришёл),
  по умолчанию печатается предупреждение, а ноты сохраняются; `--strict-eos`
  превращает это в ошибку.
- Комбинация `--batch-size > 1` с `--prelude-forcing` (включён по умолчанию)
  отклоняется с объяснением: батчинг несовместим с форсингом пролога.
- `--remove-vocals` при ошибке разделения **не откатывается** на оригинал:
  команда завершается понятной ошибкой. Стемы лежат в `<аудио>_stems/`.

## serve

```
uv run muscriptor serve [опции]
```

Поднимает HTTP-сервер: SSE-транскрипция, ноты, auralization, гитарный
аранжировщик, управление моделью и (если собрана папка `muscriptor/web_dist`)
веб-интерфейс на том же порту.

| Опция | По умолчанию | Описание |
|---|---|---|
| `--host` | `127.0.0.1` | Адрес привязки. Для доступа извне — `0.0.0.0` (см. [api.md](api.md#безопасность)). |
| `--port` | `8222` | Порт. |
| `--model`, `-m` | `medium` | Стартовая модель: ключевое слово, путь или URL. |
| `--device`, `-d` | `auto` | Устройство для модели. |
| `--dtype` | по устройству | dtype трансформера. |
| `--idle-unload` | `5` | Выгружать модель из видеопамяти после стольких минут простоя (перезагрузка из кэша занимает секунды). `0` — не выгружать. |

Модель загружается при старте (первый запуск скачивает веса). Дальше её можно
менять и выгружать прямо из веб-интерфейса или через `POST /model` — см.
[api.md](api.md#управление-моделью). Полный справочник API —
в [api.md](api.md).

## list-instruments

```
uv run muscriptor list-instruments
```

Печатает названия групп инструментов, принимаемые `--instruments` у
`transcribe` (по одному в строке). Те же имена валидны для формы
`instruments` в HTTP API и выбора в веб-интерфейсе. Полный список — в разделе
[Список инструментов](#список-инструментов).

## arrange-guitar

```
uv run muscriptor arrange-guitar ПРИМЕР.mid [опции]
```

Символьный аранжировщик: принимает **MIDI-файл (не аудио)** и для одной
дорожки подбирает струну и лад каждой ноте. По умолчанию партия сначала
**приводится к стандартному строю** (транспозиция опущенных записей и
удаление октавных дублей вне диапазона — всё в блоке `normalization`
документа), а онсеты с 7+ нотами сокращаются до играбельной подстановки
(`chord_reductions`). Начала, длительности и скорости как во входе.
Результат — детерминированный JSON schema v3 (см.
[guitar-arranger.md](guitar-arranger.md)).

| Опция | По умолчанию | Описание |
|---|---|---|
| `--output`, `-o` | `<midi>.arrangement.json` | Куда сохранить JSON. |
| `--list-tracks` | — | Показать нотные дорожки файла и выйти (без решения). |
| `--track` | авто | Индекс дорожки. Нужен, если нотных дорожек несколько. |
| `--channel` | авто | MIDI-канал внутри дорожки (0–15; 9 — ударные). |
| `--tuning` | `standard` | Пресет строя (сейчас только `standard`: E4 B3 G3 D3 A2 E2). |
| `--max-fret` | `24` | Максимальный лад, считающийся играбельным. |
| `--phrase-gap-beats` | `1.0` | Тишина такой длины (в долях) начинает новую фразу, оптимизируемую независимо. |
| `--melody` | `off` | `off` — все ноты (аккорды 1–6 нот поддерживаются); `top`/`bottom` — оставить верхнюю/нижнюю ноту только среди нот с одинаковым онсетом. |
| `--overrides` | — | JSON-файл с фиксациями: `{"version": 1, "locks": [{"note_id": …, "string": …, "fret": …}]}`. |
| `--normalize` / `--no-normalize` | вкл. | Приведение партии к стандартному строю (транспозиция + удаление внедиапазонных октавных дублей). С `--no-normalize` ноты вне диапазона — обычная ошибка. |
| `--chord-overflow` | `reduce` | Что делать с онсетами, которые нельзя сыграть целиком (нот больше струн или нет совместимой аппликатуры): `reduce` — лучшая играбельная подстановка (отчёт в `chord_reductions`), `error` — структурная ошибка. |
| `--chords` / `--no-chords` | вкл. | Определять джазовые обозначения аккордов и писать их в блок `chords` документа (их рисуют MusicXML/PDF). |
| `--explain` | выкл. | Напечатать в stderr сводку по нормализации, сокращённым онсетам, полифонии и по фразам/событиям. |

Поведение и ограничения:

- дорожка выбирается автоматически, только если нотная недрамовая дорожка
  одна; иначе — структурированная ошибка со списком кандидатов;
- один–шесть нот на одном онсете — норма; семь и более — см.
  `--chord-overflow` выше;
- нота вне диапазона грифа (низ ниже самой низкой струны или выше
  `max(открытых) + max_fret`), которую не спасла нормализация, — ошибка со
  списком всех выпавших нот; `--no-normalize` делает ошибкой любую такую ноту;
- фиксация обязана звучать ровно высоту ноты **в документе**, иначе — ошибка
  (для опущенной записи фиксации применяйте к нормализованному документу);
- асинхронные перекрытия (звенящий бас) сохраняются, но не считаются
  «тишиной» для деления на фразы; их статистика — в `polyphony_analysis`;
- `--melody top|bottom` уменьшает полифонию детерминированно; отброшенные
  ноты перечисляются в `melody_reduction`.

```bash
uv run muscriptor arrange-guitar song.mid --list-tracks
uv run muscriptor arrange-guitar song.mid --track 2 -o arrangement.json
uv run muscriptor arrange-guitar song.mid --track 2 \
    --tuning standard --max-fret 24 --phrase-gap-beats 1.0
uv run muscriptor arrange-guitar song.mid --track 2 --melody top --explain
uv run muscriptor arrange-guitar song.mid --track 2 --overrides locks.json
uv run muscriptor arrange-guitar song.mid --track 2 --no-normalize
uv run muscriptor arrange-guitar song.mid --track 2 --chord-overflow error
```

## guitar-tab

```
uv run muscriptor guitar-tab ARRANGEMENT.json [опции]
```

Превращает `arrangement.json` в читаемую ASCII-табулатуру (диагностический
текст, а не гравировка): строки 1–6 сверху вниз, сетка 16-х нот, тактовые
черты каждые 4 доли. В документе нет карты темпа/размера, поэтому это
честное приближение при `ticks_per_beat` исходника.

| Опция | По умолчанию | Описание |
|---|---|---|
| `--output` | `<arrangement>.tab.txt` | Куда записать текст. |
| `--midi` | — | Дополнительно записать MIDI. |

Обратный MIDI повторяет высоты, онсеты, офсеты и скорости документа
(минус отброшенные мелодической редукцией ноты); **выбранные струна/лад в
MIDI не сохраняются** — для этого есть MusicXML/PDF.

## guitar-musicxml

```
uv run muscriptor guitar-musicxml ARRANGEMENT.json [опции]
```

Пишет MusicXML, **сохраняющий аппликатуру**: у каждой ноты есть
`<technical><string>/<fret></technical>`, поэтому MuseScore и другие
редакторы отобразят именно выбранные позиции, включая ваши фиксации.
Обнаруженные аккорды документа пишутся как `<harmony>` **над нотоносцем**
(джазовые обозначения вместо цифр пальцев), а сами цифры левой руки по
умолчанию не выводятся — строк/ладов достаточно для табулатуры.
Накладывающиеся длительности раскладываются по голосам, длительности не
сокращаются: для неквантованного входа форма ноты — ближайший dyadic `<type>`,
а сам `<duration>` остаётся исходным. Понимаются документы schema v2 и v3
(у старых документов аккордов нет, пока их не пересчитать).

| Опция | По умолчанию | Описание |
|---|---|---|
| `--output` | `<arrangement>.musicxml` | Куда записать файл. |
| `--chords` / `--no-chords` | вкл. | Рисовать аккорды документа как `<harmony>`. |
| `--fingerings` / `--no-fingerings` | выкл. | Выводить номера пальцев левой руки (`<fingering>`). |

Особый случай: если хочется PDF (ноты + табулатура) ровно с выбранной
аппликатурой, используйте `POST /arrange/guitar/pdf` (веб-интерфейс делает это
кнопкой «PDF (ноты + таб)»), а не MIDI.

## Замечания о качестве

- По умолчанию декодирование **жадное и детерминированное** — один и тот же
  файл даёт один и тот же результат.
- `--sampling -t <T>` включает стохастику (разнообразие ценой
  воспроизводимости); `--beam-size ≥ 2` включает beam search.
- `--prelude-forcing` (по умолчанию включён) улучшает стыки чанков; отключать
  его стоит только ради батчевой скорости (`--no-prelude-forcing
  --batch-size 4`).
- `--instruments` повышает точность на известных составах: посторонние
  инструменты маскируются на уровне токенов.
