# Гитарный аранжировщик аппликатуры

Символьный модуль (`muscriptor/guitar_arrangement/`) подбирает для гитарной
партии струну и лад каждой ноты. Работает **только с MIDI** (не с аудио), без
модели, без torch, без MuseScore — на чистом Python, поэтому быстрый и
детерминированный.

Гарантии:

- высоты, начала, длительности и скорости нот **не меняются** — октавных
  переносов и транспозиции не бывает;
- ничего не отбрасывается молча: все проблемные входы дают структурированную
  ошибку (7+ нот на онсете, нота вне грифа, противоречивые фиксации);
- для одного и того же входа результат **байт-в-байт одинаков** (никаких
  таймстампов и случайностей);
- решение — оптимум относительно описанной ниже функции стоимости (глобальный
  DP по фразам), а не «идеальная аппликатура».

Где этим пользоваться:

- CLI: [`arrange-guitar`](cli.md#arrange-guitar), [`guitar-tab`](cli.md#guitar-tab),
  [`guitar-musicxml`](cli.md#guitar-musicxml);
- HTTP: [`POST /arrange/guitar`](api.md#post-arrangeguitar) и конвертеры;
- веб-интерфейс: «Гитарная лаборатория аппликатуры» (см. [ниже](#веб-лаборатория)).

## Вход и выбор дорожки

Файл читается как Standard MIDI File; ноты собираются по парам
`(дорожка, канал)`. Идентификатор ноты:

```
track:2/channel:0/note:17
```

где `17` — порядковый номер `note_on` внутри дорожки (с учётом всех каналов).
Id зависит только от исходного файла и не меняется между запусками.
`note_on` с velocity 0 трактуется как `note_off`; незакрытая нота получает
офсет в конце дорожки (нота не пропадает).

Выбор дорожки (`--track` / `--channel` в CLI, поля `track`/`channel` в API):

- ничего не указано — автоматически выбирается единственная недрамовая
  дорожка с нотами; если кандидатов несколько, возвращается ошибка со
  списком всех пар (имена дорожек для угадывания **не используются**);
- `--track N` — дорожка N; если в ней ноты на нескольких каналах, нужен
  `--channel`;
- канал 9 (ударные) доступен только явно. Строи «standard»:
  **1-я струна — самая высокая** (E4 = MIDI 64, B3 = 59, G3 = 55, D3 = 50,
  A2 = 45, E2 = 40).

## Конвейер

```
MIDI-байты
  → parse_midi            ноты + карты темпа/размера
  → select_notes          одна пара (дорожка, канал)
  → reduce_to_melody      опционально: top/bottom/off
  → group_into_events     события онсетов (1–6 нот), порядок (pitch desc, id)
  → split_event_phrases   фразы по полной тишине ≥ phrase_gap_beats
  → validate range/locks  все ошибки — до решения
  → generate_chord_shapes кандидаты на событие (инъекция струн, span, барре)
  → event DP              глобально оптимальный путь по фразе
  → to_json               детерминированный документ schema v3
```

Детали:

- **Фраза** начинается перед событием, только если все ноты, начавшиеся
  раньше, уже закончились (звенящий бас — не тишина) и пауза от **максимального**
  офсета достигает `phrase_gap_beats`. Фразы решаются независимо — но внутри
  фразы оптимизация глобальная, поэтому ранние ноты могут быть сдвинуты выше
  по грифу ради удобства поздних.
- **События** — все ноты с одинаковым онсетом. 1–6 нот — норма. Семь и более:
  ошибка `too_many_chord_notes` (ничего не удаляется; явно сократите событие
  политикой `top`/`bottom` или исправьте вход).
- **Асинхронные перекрытия** (нота звучит поверх следующего события)
  сохраняются как есть; их статистика — в `polyphony_analysis`.
  Строгое разделение голосов — задача будущего этапа.

## Алгоритм

### Кандидаты на событие

Для каждой ноты берутся все позиции `(струна, лад)`, дающие **точно ту же
высоту** (`лад = высота − открытая струна`, `0 ≤ лад ≤ max_fret`). Затем
перебираются инъективные назначения нот на струны (одна нота на струну):

- разброс зажатых ладов в форме (`max лад − min лад`) не больше
  `max_chord_fret_span` (по умолчанию 3);
- для формы выводятся позиция кисти (лад, напротив которого стоит
  указательный палец), пальцы (0 — открытая струна, 1–4) и барре — только
  если между его крайними струнами нет звучащей открытой струны;
- кандидаты сортируются канонически; при превышении `max_chord_candidates`
  лишние отбрасываются детерминированно, а в документе честно указывается
  `pruned_candidates` и `optimal_within: "retained_candidates"` (оптимум
  доказан только среди оставленных кандидатов).

Если полного назначения нет — ошибка `unplayable_chord` (например, две
одинаковые высоты с единственной позицией). Если конфликтуют фиксации —
`incompatible_chord_locks`.

### Динамическое программирование

Состояние DP — полная аппликатура события (`ChordFingeringState`): позиция
кисти, назначения струн/ладов, пальцы, барре, собственная стоимость формы.
Переход — `chord_transition_cost`:

- событие из одной ноты → используется «старая» (v2) формула поперечного
  перехода, поэтому мелодическая линия стоит ровно столько же, сколько
  раньше;
- для аккордов сравниваются позиция кисти и центр использованных струн
  (сопоставлять ноты двух аккордов один-к-одному нельзя).

Ничьи разрешаются детерминированно (лексикографически по `(стоимость,
перенос кисти, перенос по струнам)`, затем по каноническому порядку
кандидатов).

### Одиночная открытая струна далеко от порожка

Открытая струна идиоматична у порожка (позиция кисти ≤ 3) или когда звучит
одновременно с чем-то ещё (аккорд, накладывающийся голос, зафиксированная
нота). Полностью одиночная открытая нота в высокой позиции считается ошибкой
регистра: к стоимости добавляется `open_string_far_penalty` (4.0), и солвер
предпочтёт зажатую ноту в той же позиции. Штраф меньше, чем поход кистью
«туда-обратно», поэтому ноты, играбельные только открытыми (например, низкое
E), не заставляют руку ездить.

## Функция стоимости

Все веса — в `SolverConfig` (и в JSON-документе, поэтому решение
воспроизводимо):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `max_fret` | 24 | Максимальный лад |
| `phrase_gap_beats` | 1.0 | Тишина (в долях), разделяющая фразы |
| `max_hand_position` | `max_fret − 3` = 21 | Максимальная позиция кисти |
| `position_change_base` | 1.5 | Базовая цена смены позиции |
| `position_change_per_fret` | 0.75 | Плюс за каждый лад переноса |
| `string_crossing_weight` | 0.25 | Цена перехода между струнами |
| `finger_repeat_weight` | 0.1 | Слабый штраф за повторный палец со сменой лада |
| `open_string_shift_discount` | 0.5 | Смена кисти, пока звучит открытая струна, дешевле |
| `rest_gap_beats` | 0.5 | Пауза (в долях), начиная с которой перенос дешевеет |
| `rest_gap_discount` | 0.5 | Коэффициент скидки за паузу |
| `high_position_start` | 9 | Позиция, с которой начинается штраф за высокий гриф |
| `high_position_weight` | 0.05 | Слабый штраф за высокую позицию кисти |
| `max_chord_fret_span` | 3 | Максимальный разброс зажатых ладов в аккорде |
| `max_chord_candidates` | 24 | Лимит кандидатов на событие |
| `chord_span_weight` | 0.4 | Цена разброса ладов формы |
| `barre_weight` | 0.3 | Цена за каждую струну барре |
| `open_string_weight` | 0.0 | Открытые струны в форме не штрафуются |
| `open_string_free_position` | 3 | До этой позиции одиночная открытая струна бесплатна |
| `open_string_far_penalty` | 4.0 | Штраф за одиночную открытую струну выше этой позиции |
| `string_movement_weight` | 0.2 | Цена смены «центра струн» между аккордами |
| `incomplete_finger_weight` | 1.0 | Штраф, если пальцы удалось проставить не всем нотам |

Смысл: переходы между ладами внутри одной позиции бесплатны; заметно только
смещение **кисти**; открытая струна или пауза делают перенос дешевле (но не
бесплатным).

Метрики решения (в `metrics` документа): `position_change_count`,
`total_hand_position_travel`, `largest_hand_position_shift`, `open_string_count`,
`finger_usage`, `locked_notes`, `generated_candidates`/`pruned_candidates`,
`total_fret_travel`/`total_string_travel` (диагностика, это не движение кисти).

## Фиксации (locks)

Формат файла `--overrides` (и строки формы `overrides`):

```json
{
  "version": 1,
  "locks": [
    {"note_id": "track:2/channel:0/note:17", "string": 2, "fret": 5}
  ]
}
```

Правила (проверяются до решения, ошибка `invalid_overrides`, HTTP 400):

- `version` должен быть ровно `1`; `locks` — массив;
- `note_id` — непустая строка из выбранной дорожки; для неизвестного id —
  ошибка (в том числе для ноты, отброшенной политикой `top`/`bottom`);
- `string ≥ 1`, `fret ≥ 0`; струна не должна превышать количество струн,
  лад — `max_fret`;
- позиция обязана звучать **ровно исходную высоту** — иначе ошибка
  «lock would change the pitch» (транспозиции не существует);
- дубликаты `note_id` запрещены.

Зафиксированная нота получает единственного кандидата; вся фраза (включая
содержащий её аккорд) пересчитывается заново — соседние ноты двигаются так,
чтобы фраза в целом осталась удобной. Фиксации участвуют в DP как обычные
состояния, поэтому метрики и стоимость остаются честными. Веб-интерфейс
отправляет **весь набор фиксаций** на каждый клик — сервер никогда не хранит
состояние редактора.

## JSON schema v3

Документ — единственный обменный формат модуля. Схема версионирована;
конвертеры (`guitar-tab`, `guitar-musicxml`, `/arrange/guitar/*`) понимают и
старые документы schema v2 (монодокументы без `events` и карт темпа).
Верхний уровень:

```json
{
  "schema_version": 3,
  "source": { ... },
  "instrument": { ... },
  "polyphony_analysis": { ... },
  "melody_reduction": { ... },
  "config": { ... },
  "phrases": [ ... ],
  "events": [ ... ],
  "notes": [ ... ],
  "metrics": { ... }
}
```

### `source`

```json
{
  "filename": "song.mid",
  "ticks_per_beat": 480,
  "track_index": 2,
  "track_name": "Guitar",
  "channel": 0,
  "program": 24,
  "tempo_events": [{"tick": 0, "tempo": 500000, "is_default": true}],
  "time_signature_events": [
    {"tick": 0, "numerator": 4, "denominator": 4,
     "clocks_per_click": 24, "notated_32nd_notes_per_beat": 8, "is_default": true}
  ]
}
```

`tempo` — микросекунды на долю; `is_default: true` означает, что в файле
событий не было и подставлено стандартное значение (500000 µs/beat, 4/4) —
это не исходные данные, а заглушка.

### `instrument` и `config`

`instrument`: `name` (`standard_guitar`), `string_numbering`
(`1_is_highest`), `open_pitches` (струна 1 → струна 6), `max_fret`,
`max_hand_position`. `config` — полный набор весов из таблицы выше.

### `polyphony_analysis`

```json
{
  "note_count": 42, "onset_event_count": 36, "polyphonic_event_count": 5,
  "largest_onset_group": 4, "overlapping_region_count": 3,
  "max_active_notes": 4, "strictly_monophonic": false
}
```

`overlapping_region_count` — число элементарных интервалов таймлайна (разрез
по каждому онсету и офсету), где звучат две и более нот одновременно.
`strictly_monophonic` — истина, если нигде не звучит больше одной ноты, даже
на общих онсетах.

### `melody_reduction`

```json
{"policy": "off", "dropped_note_count": 0, "dropped": []}
```

При `top`/`bottom` — список отброшенных нот `{"tick": …, "pitch": …}`.
Оставшиеся ноты сохраняют идентичность (id, тайминги, velocity) — редукция
не подрезает длительности.

### `phrases`, `events`, `notes`

`phrases[i]` — `{index, start_tick, end_tick, cost, event_count, fret_travel,
string_travel}`.

`events[i]` (по одному на онсет; порядок — по фразам, внутри — по времени):

```json
{
  "id": "event:0",
  "index": 0,
  "phrase": 0,
  "onset_ticks": 0,
  "note_ids": ["track:2/channel:0/note:1"],
  "hand_position": 5,
  "barres": [{"finger": 1, "fret": 5, "from_string": 1, "to_string": 3,
              "note_ids": ["track:2/channel:0/note:1", "…"]}],
  "shape_cost": 0.35,
  "finger_assignment_complete": true,
  "generated_candidates": 12,
  "pruned_candidates": 0,
  "optimal_within": "all_candidates"
}
```

`notes[i]` — плоский список (для редактора и фиксаций), порядок — фраза, затем
`(онсет, высота по убыванию, id)`:

```json
{
  "id": "track:2/channel:0/note:1",
  "event_id": "event:0",
  "phrase": 0,
  "pitch": 64,
  "onset_ticks": 0,
  "offset_ticks": 480,
  "velocity": 100,
  "string": 1,
  "fret": 0,
  "hand_position": 1,
  "finger": 0,
  "locked": false,
  "legal_positions": [{"string": 1, "fret": 0}, {"string": 2, "fret": 5}],
  "legal_fingerings": [
    {"string": 1, "fret": 0, "hand_position": 1, "finger": 0},
    {"string": 2, "fret": 5, "hand_position": 5, "finger": 1}
  ]
}
```

- `finger`: 0 — открытая струна, 1–4 — указательный…мизинец; **`null`**, если
  аннотация пальцев получилась неполной (тогда
  `finger_assignment_complete: false` у события и `"unknown"` в
  `finger_usage`). Струна/лад при этом валидны.
- `legal_positions` — все позиции этой ноты; `legal_fingerings` — все полные
  состояния для неё (для открытой струны — по одному состоянию на каждую
  допустимую позицию кисти).

### `metrics`

```json
{
  "note_count": 42, "phrase_count": 4, "event_count": 36, "total_cost": 12.75,
  "position_change_count": 3, "total_hand_position_travel": 7,
  "largest_hand_position_shift": 4, "open_string_count": 5,
  "finger_usage": {"0": 5, "1": 20, "2": 9, "3": 5, "4": 3, "unknown": 0},
  "generated_candidates": 230, "pruned_candidates": 18,
  "total_fret_travel": 21, "total_string_travel": 14,
  "largest_fret_transition": 5, "largest_string_transition": 2,
  "locked_notes": 0
}
```

## Коды ошибок

| Код | HTTP (API) | Когда |
|---|---|---|
| `invalid_midi` | 400 | Файл не читается как MIDI |
| `invalid_overrides` | 400 | Неизвестный строй, битый JSON фиксаций, лок не на ту высоту/струну/лад, дубликат |
| `invalid_melody_policy` | 400 | Политика не из `off`/`top`/`bottom` |
| `track_not_found` | 422 | Нет нотных дорожек / нет нот на выбранном канале |
| `ambiguous_track` | 422 | Несколько кандидатов; `details.tracks` — список для выбора |
| `unplayable_note` | 422 | Нота вне диапазона грифа; `details` — pitch/low_pitch/high_pitch и агрегированный список выпавших нот |
| `too_many_chord_notes` | 422 | 7+ нот на онсете; `details` — событие и число струн |
| `unplayable_chord` | 422 | Нельзя развести ноты по струнам |
| `incompatible_chord_locks` | 422 | Фиксации аккорда противоречат друг другу |
| `polyphonic_input` | 422 | Только для устаревшего монопути (`check_monophonic`); конвейер v3 его не бросает |
| `invalid_arrangement` | 400 | Документ не JSON / не проходит валидацию конвертера |
| `unsupported_arrangement_schema` | 400 | `schema_version` не 2 и не 3 |
| `fingering_export_failed` | 500 | MuseScore не смог записать PDF |

Ответ API: `{"detail": {"code", "message", "details"}}`. Сообщения написаны
для человека: CLI печатает их как есть, UI показывает локализованную
формулировку для известных кодов.

## Экспорт

| Формат | Команда / эндпоинт | Сохраняет аппликатуру? |
|---|---|---|
| JSON | `arrange-guitar`, `POST /arrange/guitar` | да (это и есть документ) |
| MIDI | `guitar-tab --midi`, `POST /arrange/guitar/midi` | **нет**: MIDI хранит только ноты/тайминги/velocity |
| ASCII-таб | `guitar-tab`, `POST /arrange/guitar/tab` | да (текст по выбранным позициям; сетка 16-х, черты каждые 4 доли) |
| MusicXML | `guitar-musicxml`, `POST /arrange/guitar/musicxml` | да: `<technical><string>/<fret></technical>` у каждой ноты |
| PDF | `POST /arrange/guitar/pdf` | да: MusicXML → MuseScore, zip с `full_score.pdf` и MusicXML |

Почему PDF именно так: скормить MuseScore обычный MIDI нельзя — его
авто-табулатура придумает собственные позиции. MusicXML с техническими
элементами заставляет гравировщика сохранить ровно выбранные струны и лады.

## Веб-лаборатория

«Гитарная лаборатория аппликатуры» (кнопка «Исправить аппликатуру»):

- вход: MIDI текущей транскрипции (без повторной загрузки) или любой
  `.mid`/`.midi` с экрана загрузки; при нескольких нотных дорожках — выбор;
- SVG-гриф: выбранная нота, её допустимые позиции и фиксации; барре; весь
  аккорд на экране; навигация стрелками по событиям и нотам внутри аккорда;
- клик по позиции фиксирует ноту (весь набор фиксаций уходит на сервер,
  ответ заменяет всю аппликатуру; при ошибке набор откатывается к последнему
  подтверждённому);
- выбор мелодической политики: «Все ноты», «Верхняя нота», «Нижняя нота»;
- метрики: смены позиции, переносы кисти, наибольший сдвиг, стоимость фразы,
  число зафиксированных нот;
- прослушивание на условных **120 BPM** (в документе нет карты темпа;
  относительный ритм точен);
- скачивания: `arrangement.json`, `arrangement.mid`, ASCII-таб (`.txt`),
  MusicXML и ZIP (PDF + MusicXML).

## Ограничения

- Только **standard tuning**; пресет задаётся `--tuning standard`.
- Строгое разделение голосов (мелодия отдельно, бас отдельно) не делается;
  «верхняя/нижняя нота» — это отбор в пределах одного онсета, а не анализ
  голосов.
- Строй/каподастр, флажолеты, бенды и прочие техники не моделируются.
- Кандидаты на событие ограничены `max_chord_candidates`; при сокращении
  документ честно сообщает, что оптимум доказан только среди оставшихся.
