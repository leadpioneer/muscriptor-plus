# HTTP API

Сервер (`uv run muscriptor serve`, по умолчанию `127.0.0.1:8222`) отдаёт
FastAPI-приложение. Все эндпоинты принимают `multipart/form-data`; JSON-тела
Multipart-поля с несколькими значениями (например, `instruments`) передаются
повторением имени поля. Спецификация доступна в интерактивном виде по
`/docs` (Swagger UI) — включена FastAPI по умолчанию.

## Общие коды ошибок

| Код | Когда |
|---|---|
| `400` | Некорректный запрос: файл не декодируется, неизвестное имя инструмента, битый JSON/документ, неизвестный mode |
| `413` | Аудио длиннее 15 минут (только `/transcribe/midi`) |
| `422` | Доменная ошибка аранжировщика (неоднозначная дорожка, неполифонически играбельный аккорд, ошибка разделения) или провал определения темпа при `detect_tempo=true` |
| `409` | Модель загружается, или идёт транскрипция — операция отклонена |
| `501` | Возможность недоступна на этом сервере (нет загрузчика модели) |
| `503` | Сервер занят другой транскрипцией; MuseScore не установлен; не удалось перезагрузить модель |
| `500` | Внутренняя ошибка (FluidSynth, MuseScore упал, ошибка генерации PDF) |

Ошибки FastAPI имеют вид `{"detail": ...}`; у гитарного аранжировщика
`detail` структурирован: `{"code": "...", "message": "...", "details": {...}}`
(коды — в [guitar-arranger.md](guitar-arranger.md#коды-ошибок)).

## GET /health

```json
{"status": "ok"}
```

Используется `start.bat` и фронтендом для проверки живости сервера.

## GET /instruments

```json
{"instruments": ["acoustic_piano", "electric_piano", ..., "drums"]}
```

Полный список — в [cli.md](cli.md#список-инструментов). Форма `instruments`
у эндпоинтов принимает только эти точные имена (в отличие от CLI, где
допустимы однозначные сокращения).

## GET /soundfonts/MuseScore_General.sf3

Отдаёт сжатый звуковой шрифт (38 МБ) для встроенного синтезатора браузера.
При первом запросе скачивается с HuggingFace и кэшируется; отдаётся как
`application/octet-stream`.

## POST /transcribe (SSE)

Транскрипция аудио с потоковой отдачей событий.

Поля формы:

| Поле | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `file` | да | — | Аудиофайл (WAV или формат libsndfile) |
| `instruments` | нет | — | Имена групп инструментов; можно повторять поле. Жёсткое ограничение декодирования |
| `detect_tempo` | нет | `best-effort` | `true` / `false` / `best-effort` (см. ниже) |
| `remove_vocals` | нет | `false` | Удалить ведущий вокал и расшифровать инструментал |

Заголовок `X-Client-Id` (необязательный) включает [преемпцию
переотправки](#конкурентность-и-блокировка).

Ответ: `text/event-stream` (`Cache-Control: no-cache`,
`X-Accel-Buffering: no`). Кадр — одна строка `data: <json>`; типы событий:

| `type` | Поля | Когда |
|---|---|---|
| `start` | `pitch`, `start_time`, `index`, `instrument` | начало ноты |
| `end` | `end_time`, `start_event_index` | конец ноты (парный к `start` по `index`) |
| `progress` | `completed`, `total` | грубые якоря прогресса: приходит один с `completed=0` в начале, затем после каждого готового чанка |
| `stage` | `stage` | только при `remove_vocals=true`: `prepare`, `vocal_removal`, `instrumental`, `transcription`, `midi` |
| `transcription_complete` | `data`, `quantized_midi`, `beat_grid`, `stems`, `from_instrumental` | финальное событие |
| `error` | `detail` | терминальная ошибка: сбой препроцессинга, провал детекции темпа при `detect_tempo=true` или ошибка перезагрузки модели; транскрипция не запускалась |

`transcription_complete`:

```json
{
  "type": "transcription_complete",
  "data": "<base64-encoded .mid>",
  "quantized_midi": "<base64-encoded .mid> или null",
  "beat_grid": {"bpm": 128.0, "beats_per_bar": 4, "first_downbeat": 0.42, "onset_delay": 0.018},
  "stems": {"vocals": "/stems/<id>/vocals", "instrumental": "/stems/<id>/instrumental"},
  "from_instrumental": true
}
```

- `data` — MIDI с уже учтённым `onset_delay` (задержкой онсетов),
  темпом/размером и сдвигом тактовых черт.
- `quantized_midi` — та же запись, притянутая к сетке; именно её надо
  отправлять в `/sheets` с `quantized=true` (или `null`, если сетки не было).
- `beat_grid` — `null`, если устойчивый темп не найден.
- `onset_delay` — на сколько «опаздывают» уже отданные в стриме события
  `start` относительно сетки; MIDI уже сдвинут, **клиент стрима должен сам
  вычесть это значение** из нарисованных нот.
- `stems`/`from_instrumental` добавляются только на пути с удалением вокала
  (для обычного прогона финальное событие не меняется).

Особенности:

- `/transcribe` **не ограничивает длительность** аудио (ограничение есть
  только у `/transcribe/midi`).
- При `detect_tempo=true` провал детекции темпа завершает поток событием
  `error` — клиент всегда получает терминальное событие. `best-effort`
  (по умолчанию) вместо ошибки пишет предупреждение в лог и отдаёт файл без
  сетки; `false` отключает детекцию.
- Стемы доступны по ссылкам из `stems` ограниченное время (см.
  [GET /stems](#get-stemsrun_idstem)).

## POST /transcribe/midi

То же, что `/transcribe`, но без стрима: запрос блокируется до конца
транскрипции и возвращает готовый файл.

- Поля те же (`file`, `instruments`, `detect_tempo`, `remove_vocals`).
- Ответ: `audio/midi`, `Content-Disposition: attachment; filename="result.mid"`.
- Аудио длиннее **15 минут** отклоняется с `413`.
- `remove_vocals=true` работает, но стемы **не сохраняются** (удаляются сразу
  после запроса).
- Ошибка разделения — `422`; провал темпа при `detect_tempo=true` — `422`;
  занятый сервер — `503`.
- `/transcribe/midi` сам не отменяем: он не стримит, останавливать нечего.
  Поэтому переотправка от того же клиента во время его выполнения получит
  `503` (а не преемпцию). Обратное работает: новый `/transcribe/midi` может
  отменить более ранний SSE-прогон того же клиента.

## POST /sheets

Гравировка **загруженного MIDI** (не аудио) в ноты.

Поля: `midi` — файл `.mid`/`.midi`; `quantized` — `true`, если ноты уже
притянуты к сетке (обычно это `quantized_midi` из `/transcribe`).

Ответ: `application/zip`, имя `sheets.zip`. Упаковано **без сжатия**; внутри:

| Файл | Что это |
|---|---|
| `score.mid` | загруженный MIDI как есть |
| `score.musicxml` | партитура MusicXML |
| `full_score.pdf` | полная партитура |
| `NN_<part>.pdf` | PDF по инструменту (NN — позиция в партитуре) |
| `NN_<part>_tab.pdf` | табулатура для ладовых партий (4–9 струн) |

- `503`, если MuseScore не найден; `500`, если MuseScore не смог ничего
  записать (чаще всего — загружен не MIDI).
- Никакие файлы не остаются на диске сервера: всё гравируется во временном
  каталоге.

## POST /auralize

Синтез MIDI через FluidSynth в WAV.

| Поле | Обязательно | Описание |
|---|---|---|
| `midi` | да | MIDI-файл |
| `audio` | для `mode=mix` | Оригинальное аудио |
| `mode` | нет (`mix`) | `mix` — стерео L=оригинал, R=синтез; `synth` — моно, только синтез |

Ответ: `audio/wav`. `400` — неизвестный режим или отсутствует `audio` при
`mix`; `500` — FluidSynth недоступен или упал. Синтез RMS-нормализуется под
оригинал; записанная в MIDI задержка тактовой черты вычитается, чтобы
дорожки совпадали по времени.

## POST /arrange/guitar

Гитарная аппликатура для MIDI-файла. Тело — форма:

| Поле | По умолчанию | Описание |
|---|---|---|
| `file` | — | MIDI-файл |
| `track` | авто | Индекс дорожки |
| `channel` | авто | Канал (0–15; 9 — ударные) |
| `tuning` | `standard` | Пресет строя |
| `max_fret` | `24` | Максимальный лад |
| `phrase_gap_beats` | `1.0` | Тишина (в долях), начиная с которой фраза делится |
| `melody` | `off` | `off` / `top` / `bottom` |
| `overrides` | — | Строка JSON с фиксациями (`{"version":1,"locks":[…]}`) |
| `normalize` | `true` | Привести партию к стандартному строю (транспозиция + удаление внедиапазонных октавных дублей), отчёт — в блоке `normalization` |
| `chord_overflow` | `reduce` | Что делать с онсетами, которые нельзя сыграть целиком (нот больше струн или нет совместимой аппликатуры): `reduce` — сократить до лучшей играбельной подстановки (отчёт в `chord_reductions`); `error` — вернуть структурную ошибку |
| `chords` | `true` | Определить джазовые обозначения аккордов и записать их в блок `chords` документа |

Ответ: JSON-документ schema v3 (`Content-Type: application/json`), включая
производные блоки `normalization`, `chord_reductions` и `chords`.
Структурированные ошибки: `400` для нечитаемого MIDI, неизвестного строя,
битых фиксаций и неверной мелодической политики; `422` для неоднозначной
дорожки, ноты вне грифа (после нормализации) и неиграбельного онсета при
`chord_overflow=error`. Полный разбор — в
[guitar-arranger.md](guitar-arranger.md).

## Конвертеры arrangement.json

Все четыре эндпоинта принимают форму с полем `document` —
подтверждённый `arrangement.json` (schema v2 или v3):

| Эндпоинт | Ответ |
|---|---|
| `POST /arrange/guitar/midi` | `audio/midi`, имя `<stem>.mid`. Высоты/тайминги/скорости как в документе; выбранные струна/лад в MIDI не переносятся |
| `POST /arrange/guitar/tab` | `text/plain; charset=utf-8` — ASCII-табулатура (сетка 16-х, черты каждые 4 доли) |
| `POST /arrange/guitar/musicxml` | `application/vnd.recordare.musicxml+xml` — MusicXML с `<technical><string>/<fret></technical>` у каждой ноты; поля формы `chords` (по умолчанию `true` — рисовать блок `chords` как `<harmony>`) и `fingerings` (по умолчанию `false` — номера пальцев левой руки) |
| `POST /arrange/guitar/pdf` | `application/zip`, имя `<stem>_score.zip`: `full_score.pdf` (ноты + табулатура + аккорды, MuseScore) и `<stem>.musicxml`; поля формы `chords`/`fingerings` — как выше |

`400` — документ не JSON или не проходит валидацию (в том числе
неподдерживаемая `schema_version` или неизвестный код качества аккорда).
`pdf` дополнительно: `503`, если нет
MuseScore; `500` (`{"code": "fingering_export_failed", ...}`), если MuseScore
не смог записать PDF.

## GET /stems/{run_id}/{stem}

Скачивание стема разделения вокала. `stem` — `vocals` или `instrumental`
(ровно те имена, что в `stems` финального события). Ответ — `audio/wav` с
`Content-Disposition: attachment`.

- `404`, если прогон неизвестен/истёк или разделение не использовалось.
- Записи живут **1 час** от создания и не более **8 прогонов** на сервере
  (более старые удаляются); директории брошенных прогонов подчищаются перед
  каждым новым разделением.
- Стемы появляются только у `/transcribe` с `remove_vocals=true`;
  `/transcribe/midi` их не сохраняет.

## Управление моделью

### GET /model

```json
{"model": "medium", "status": "ready", "error": null}
```

`status`: `ready`, `loading`, `error`, `unloaded`. Поле `model` — реальный
идентификатор: ключевое слово размера (`small`/`medium`/`large`) или путь,
с которого сервер стартовал.

### POST /model

Поле формы `size`: `small` | `medium` | `large` | `unload`.

- `small`/`medium`/`large` — запускает фоновую загрузку и сразу возвращает
  `{"model": "<текущий>", "status": "loading"}`; по завершении модель
  атомарно замещается, старая память освобождается.
- `unload` — выгружает модель (эквивалент кнопки «выгрузить»); следующий
  запрос загрузит её из кэша.
- `400` — неизвестный размер; `409` — уже идёт загрузка или транскрипция;
  `501` — на этом сервере нет загрузчика (сервер без поддержки переключения).
- Повторный `POST` с текущим размером в состоянии `ready` — no-op.

Выгрузка по простою: сервер с `--idle-unload N` выгружает модель после N
минут без запросов (по умолчанию 5; `0` отключает). Проверка выполняется
фоновым потоком не чаще раза в 30 секунд.

## Конкурентность и блокировка

На сервере одновременно выполняется **не более одной** транскрипции или
разделения вокала (общая блокировка). Поведение зависит от заголовка
`X-Client-Id`:

- **Другой клиент** (или его нет) получает `503 {"detail": "server busy:
  another transcription is in progress"}` немедленно — без ожидания в
  соединении. Это позволяет балансировщику (например, Traefik) сразу
  отправить повтор на другую реплику.
- **Тот же клиент** (веб-интерфейс отправляет стабильный id вкладки):
  его предыдущий прогон мягко отменяется (событие отмены проверяется на
  каждом чанке), новый запрос ждёт освобождения блокировки до 5 секунд,
  после чего получает `503`.
- Веб-интерфейс при `503` автоматически повторяет попытку каждые 5 секунд и
  показывает «Серверы заняты, повтор через N с».

## Безопасность

- Аутентификации, CORS-заголовков и ограничения частоты запросов нет:
  сервер рассчитан на локальный запуск (`127.0.0.1`) или на размещение за
  доверенным прокси. Не выставляйте его в интернет напрямую.
- Загрузки не сохраняются между запросами, кроме стемов вокала (временный
  каталог, TTL — см. выше) и файлов нот (тоже временные, удаляются сразу).
- Для публичного развёртывания используйте Docker/Swarm-схему репозитория с
  Traefik (TLS, доступ-логи) — см.
  [architecture.md](architecture.md#развёртывание-сервера).
